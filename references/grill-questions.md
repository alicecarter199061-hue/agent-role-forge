# 角色需求审问问题库

审问目的：**动手写 prompt 前，把角色需求问清楚**。需求不清时角色必歪——多花 2 分钟审问，省 2 小时返工。

使用原则：
- 按需提问，**已明确的项跳过**，不问废话。
- 用户说"直接干 / 轻量 / 快速出稿"时降级为 1 轮快速确认（只问：目标 + 边界）。
- 问题按"必问 5 项"优先，其余为补充深入项。

---

## 第 0 步：角色结构判断（智能调度入口）

**先判断执行模式再往下问**——决定整个流程走单角色还是团队：

> 这个任务是**一个角色独立完成**，还是需要**多个角色协作**（一个团队）？

触发词自动识别：
- 用户说"造**几个**角色 / **小队** / **团队** / **分工** / **协作** / **一组** / 某项目**全套**agent" → **team** 模式
- 用户说"造**一个**角色 / 帮我设计**一个** persona" → **single** 模式
- 不确定时：直接问一句"一个角色够，还是要一组角色协作？"

| 模式 | 含义 | 流程 |
|---|---|---|
| `single`（默认） | 一次审问 → 一个角色 | 标准 6 步 |
| `team` | 全局审问一次 + 逐个角色审问 → N 份 prompt + 角色分工表 | 见下节「团队审问」 |

> 中途发现也可切换：审问到一半发现用户要的其实是团队，切 `team`；反之亦然。在需求卡里标注模式。

---

## 必问 5 项（Step 1 核心，single 模式 / team 模式全局项）

### 1. 角色目标
> 这个 agent 到底要完成什么任务？完成到什么程度算成功？

- 追问：它产出什么（代码/文本/分析/操作）？交付物是什么？
- 反例判断：答不出"成功长什么样" → 继续追问到可验收。

### 2. 触发场景
> 它什么时候被调用？

- 对话中被用户召唤？
- 作为子代理/后台任务自动跑？
- 定时/事件触发？
- 多 agent 协作里的固定角色？

### 3. 平台约束
> 它跑在哪个平台？用什么模型？

- Multica（agent + skill 挂载）/ WorkBuddy（SOUL/IDENTITY 人格）/ Codex（agents/*.toml）/ Claude Code（subagents）/ ZCode（skill / AGENTS.md）
- 模型能力上限（推理强/弱、上下文大小、是否支持工具）——影响 prompt 复杂度设计。

### 4. 工具权限
> 它能用什么？绝对不能碰什么？

- 允许：读文件/写文件/执行命令/调 API/发消息/浏览器/生图/网络搜索…
- 禁止：外部发布、删除数据、花钱动作、敏感区写入…
- 关键：**权限边界必须写进 prompt 的约束节**，这是防越权的主体。

### 5. 风格语气
> 它说话/输出的风格？

- 语气：正式/简洁/幽默/冷酷/教练式…
- 篇幅：极短结论 / 详细报告 / 代码优先…
- 输出格式：纯文本 / markdown / 结构化 JSON / 表格…

## 团队审问（team 模式专用）

### T1. 团队结构
> 团队有几个角色？分别是什么？

- 用户给角色清单 → 记下；用户只给任务 → 按任务拆解建议角色（参考 MetaGPT SOP / CrewAI 分工），让用户确认或调整。
- 每个角色一句话定位（它负责哪一段）。

### T2. 协作关系
> 角色之间什么关系？

- **指挥/执行分离**（参考 D1）：有一个"总指挥/编排"角色调度其他角色，还是平级协作？
- 串行流水线（A 做完交给 B）还是并行分工（各自独立）？
- 谁汇总最终结果？

### T3. 共享项（问一次，全队沿用）
> 团队共用哪些设定？

- 平台模型：通常全队同一个平台；模型可按角色分工有强有弱（如指挥=强推理，执行=低成本）。
- 全局权限边界：哪些动作全队禁止（如对外发布）？
- 全局风格：对话语言、报告风格。

### T4. 差异项（逐角色问）
> 每个角色单独确认？

- 该角色目标（负责哪一段）、触发（被谁调用）、专属工具/权限、语气风格。
- 共享项已知的直接沿用，不重复问。

### 团队需求卡（进入 DIY 前的输入）

```
模式:     team（N 个角色）
团队目标: <整队要完成的最终交付>
平台模型: <全局平台+模型，可标注角色差异>
共享权限: 允许: <…>  禁止: <…>
协作关系: <总指挥是谁 / 串行或并行 / 谁汇总>

角色清单:
  角色1「名称」: 定位=<负责哪段>  触发=<被谁调>  专属工具=<…>  风格=<…>
  角色2「名称」: …
  ...
```

## 补充深入项（按需，single / team 通用）

### 6. 背景知识
> 它需要什么领域知识？有没有内部资料/文档/知识库要挂？

- 决定是否需要 skill / RAG / 记忆层（参考 Mem0/Letta 机制）。

### 7. 角色个性
> 它有"人设"吗？（名字、称呼、口头禅、世界观）

- 纯工具型 agent：不需要，跳过。
- 陪伴/创作型：要，参考 openclaw-persona-forge 式的人设维度。

### 8. 失败处理
> 遇到不会的/失败的任务怎么办？

- 报错给用户？重试？降级方案？静默跳过？
- 参考"错误处理降级不中断"模式（见 SKILL.md 错误处理节）。

### 9. 多角色协作
> 它是不是团队的一员？和其他 agent 什么关系？

- 独立干完 / 分工协作 / 指挥者 / 被指挥者。
- 参考 CrewAI/MetaGPT 的协作分工机制。（team 模式必问，见 T2）

### 10. 验收标准
> 怎么算这个角色（或团队）合格？

- 用户给 1 个验收用例（试一次就知道行不行）。
- 或列出 2~3 条可检查的硬指标。

## 审问速查表（对话模板）

### single 模式
```
关于这个角色，我需要确认 3 件事（其余我按通用方案处理）：
1. 它要完成什么任务、成功长什么样？
2. 它跑在哪个平台、用什么模型？
3. 绝对不能做什么？（权限边界）

——如果答案里有不清楚的，逐条追问；都清楚了，进入取材 + DIY。
```

### team 模式
```
我先确认团队结构，再逐个角色确认：
1. 这个团队要完成什么？拆成哪几个角色？（我按任务建议，你确认）
2. 角色之间怎么配合——有没有总指挥？串行还是并行？
3. 团队共用：平台/模型、全队禁止做的事、通用风格？

然后逐个角色问：它负责哪段、被谁调用、专属权限、语气。

——都清楚了，按角色逐个取材 + DIY，最后给你分工表 + 每份 prompt。
```

## 审问输出（进入 DIY 前的输入）

审问结束后应得到一张「角色需求卡」：

```
模式:     <single / team>
目标:     <一句话>（team: 团队目标 + 角色清单）
触发场景: <对话/子代理/定时/协作>
平台模型: <平台 + 模型>
权限:     允许: <…>  禁止: <…>
风格:     <语气 + 篇幅 + 格式>
边界/禁忌: <明确不做的事>
协作关系: <team 模式: 指挥/串并行/汇总>
```

需求卡齐了才进入 Step 2 取材；缺关键项就继续审问。
